Section 01

Project Overview

ECO-3D Studio is a geospatial AI platform for sustainable architecture site analysis and floor plan generation. It solves the problem that traditional building site assessment requires expensive on-site surveys, manual environmental research, and separate architectural tools — a process that takes weeks and costs thousands. ECO-3D collapses this into a ~10-second automated pipeline driven by a GPS coordinate.

Full Pipeline

  1. User selects a plot by clicking on a Leaflet satellite map. Coordinates and polygon captured.
  2. Satellite tile fetched (224×224 Mapbox). DeepLabV3 ResNet-50 classifies every pixel: vegetation, water, urban, road, bare soil.
  3. YOLOv8n detects trees on the same tile, converting bounding boxes to geographic lat/lon coordinates.
  4. 7 public APIs queried in parallel: Open-Elevation, Open-Meteo (wind + ERA5 rainfall), SoilGrids v2, NASA POWER, GloFAS, OSM Overpass, NOAA formula.
  5. XGBoost predicts flood probability. MLP neural network (64→32→16) predicts buildability score [0–100].
  6. Genetic Algorithm (pop=60, gen=80) generates an eco-optimized floor plan with rooms, walls, doors, windows.
  7. 3D model rendered in WebGL via React Three Fiber with procedural textures and live sun simulation.

Section 07.1

DeepLabV3 ResNet-50 — Semantic Segmentation

Conceptual Intuition

DeepLabV3 labels every pixel with a semantic class. Where a classification network asks "what is in this image?", DeepLabV3 asks "what category does each pixel belong to?" — effectively colouring a painting where every colour has meaning: green = vegetation, blue = water, gray = urban. Chosen because it's pretrained on Pascal VOC (21 classes that map directly to ECO-3D's land-cover categories) and runs CPU-feasibly at 224×224.

Mathematical Foundation

ResNet residual connection: H(x) = F(x) + x ASPP dilated convolution (rate r): (F ★ w)[i,j] = Σₘ Σₙ F[i + r·m, j + r·n] · w[m,n] Classification + fractions: ŷᵢⱼ = argmax_c L[i,j,c] (L = logit tensor ℝ^{H×W×21}) fraction_c = count(mask == c) / (H × W) ImageNet normalisation: x_norm = (x − μ) / σ μ = [0.485, 0.456, 0.406], σ = [0.229, 0.224, 0.225]

Input → Output

Input:   lat, lon → Mapbox 224×224 RGB [H=224,W=224,C=3, uint8]
  ↓ T.ToTensor() + T.Normalize(μ,σ) → [3,224,224] float32
  ↓ DeepLabV3 ResNet-50 + ASPP (rates 1,6,12,18) → logits [1,21,224,224]
  ↓ argmax → class map [1,224,224]
  ↓ remap: vegetation={9,4,17}, water={21,60}, urban={0,1,2,25}, road={6,11}
Output:  {vegetation:0.43, water:0.06, urban:0.18, road:0.05, bare_soil:0.28}

Worked Numerical Example

Pixel [0,0]: R=120, G=180, B=90 After normalise: [0.480, 1.121, -0.235] logit[vegetation]=2.3, logit[road]=-0.8 P(veg) = exp(2.3)/(exp(2.3)+exp(-0.8)) = 9.97/10.42 = 0.957 → vegetation ✓

Section 07.2

YOLOv8n — Tree Detection

Mathematical Foundation

YOLO detection head per grid cell (i,j): bx = σ(tx) + cx, by = σ(ty) + cy (centre, sigmoid-normalised) bw = pw × e^{tw}, bh = ph × e^{th} (width/height, anchor-relative) Pixel → geographic coordinate (Web Mercator): meters_per_pixel = 156543.03392 × cos(lat_rad) / 2^{zoom} Δlat = dy_metres / 111320.0 Δlon = dx_metres / (111320.0 × cos(lat_rad))

Worked Numerical Example

Tile: 224×224, lat=8.5241, lon=76.9366, zoom=15 Box centre: (115, 75). Tile centre: (112, 112). meters_per_pixel = 156543.03 × cos(8.52°) / 32768 = 4.726 m/px dx_m = (115-112) × 4.726 = 14.18 m dy_m = (112-75) × 4.726 = 174.86 m Δlon = 14.18 / (111320 × 0.989) = 0.0001287° Δlat = 174.86 / 111320 = 0.0015709° → tree at (8.5257, 76.9367) ✓
Section 07.3

XGBoost — Flood Risk Regression

Mathematical Foundation

Model: F(x) = Σ_{k=1}^{200} f_k(x) (sum of 200 regression trees) Objective: L = Σᵢ (ŷᵢ − yᵢ)² + Σ_k Ω(f_k) Ω(f) = γ·T + ½·λ·‖w‖² (T=leaf count, w=leaf weights) Gradient boosting update at step t: L̃^{(t)} ≈ Σᵢ [gᵢ·fₜ(xᵢ) + ½·hᵢ·fₜ(xᵢ)²] + Ω(fₜ) Optimal leaf weight: w*_j = −G_j / (H_j + λ) Preprocessing: x' = (x − μ_train) / σ_train (StandardScaler)

MLP Neural Network — Buildability Score

Mathematical Foundation

Forward pass: z¹ = ReLU(W¹·x + b¹) x ∈ ℝ^6 → z¹ ∈ ℝ^{64} z² = ReLU(W²·z¹ + b²) → z² ∈ ℝ^{32} z³ = ReLU(W³·z² + b³) → z³ ∈ ℝ^{16} ŷ = W⁴·z³ + b⁴, clip(ŷ, 0, 100) Adam optimiser: m_t = β₁·m_{t-1} + (1−β₁)·∇L v_t = β₂·v_{t-1} + (1−β₂)·(∇L)² θ_{t+1} = θ_t − α · m̂_t / (√v̂_t + ε) Backprop through ReLU: ∂L/∂z = ∂L/∂a ⊙ 𝟙[z > 0]
Section 07.5

Genetic Algorithm — Floor Plan Optimizer

Mathematical Foundation

Fitness function (higher = better layout): fitness(C) = f_solar + f_ventilation − f_tree_penalty − f_slope_penalty + 10 f_solar = 30 × (cos(θ)×0.5 + 0.5) × (sun_h / 12) f_ventilation = 20 × min(2, width/height) / 2 f_tree_penalty = Σ_tree Σ_room max(0, 40×(r_root−dist)/r_root) f_slope_penalty = (slope/30)×(area/300)×15 Crossover (single-point): child.rooms = p1.rooms[:split] + p2.rooms[split:] child.θ = (p1.θ + p2.θ) / 2 Mutation (P = 0.15): room.x += U(−3,3), room.y += U(−3,3) θ += U(−30,30) mod 360

Section 07.6

Environmental Data APIs

NOAA Sun Hours Formula

δ = 23.45° × sin(360/365 × (DOY − 81)) (solar declination) cos(ω) = −tan(φ) × tan(δ) (hour angle at sunset) sun_hours = 2ω / 15 (φ = latitude in degrees)

Physics Flood Risk (Fallback)

elev_r = max(0, 1 − elevation/80) slope_r = max(0, 1 − slope/12) rain_r = clip((rainfall−300)/2700, 0, 1) risk = 0.40·elev_r + 0.18·slope_r + 0.14·rain_r + 0.12·clay + 0.10·water_r if GloFAS available: risk = 0.70·topo + 0.30·glofas_index

SoilGrids v2 Unit Conversions

clay_pct = clay_raw / 10.0 (SoilGrids stores g/kg × 10) soil_pH = phh2o_raw / 10.0 (stored as pH × 10) bulk_density = bdod_raw / 100.0 (cg/cm³ → g/cm³)

Section 08

Complete Pipeline Walkthrough

User clicks a plot on the Leaflet map at /map. setSelectedLocation(8.5241, 76.9366) fires, Zustand derives currentPlotId = "PLOT8524X76936". POST /analyze-plot dispatches to FastAPI. CORS middleware passes the cross-origin request. run_full_analysis() issues asyncio.gather() for three concurrent branches.

Branch 1 — DeepLabV3 (~800ms CPU): 224×224 Mapbox tile fetched → ToTensor + Normalize → ResNet-50 backbone → ASPP → argmax → land fractions: {veg:0.43, water:0.06, urban:0.18, road:0.05, bare:0.28}.

Branch 2 — YOLOv8n (~120ms CPU): Same tile → 4 tree detections above 0.30 confidence → Mercator pixel→geo conversion → List[TreeCoordinate].

Branch 3 — Real Env Data (~6–10s, network bottleneck): 7 HTTP requests simultaneously: elevation=42m slope=3.1° · wind=4.2m/s NE · rainfall=2800mm/yr · SoilGrids: clay=38% → "Clay Loam" buildable=True · NDVI_proxy=0.61 · GloFAS: glofas_index=0.12 · water distance=340m · sun_hours=13.3h.

XGBoost: [42, 3.1, 0.61, 2800, 2, 340] standardised → 200 trees → flood_probability = 0.2341.

MLP: [0.2341, 3.1, 0.62, 0.61, 0.28, 13.3] → 64→32→16→1 ReLU → buildability_score = 74.2 → status = "GOOD".

DB persisted, HTTP 200 JSON returned. Axios receives (~8–12s total). Zustand updates. UI renders at /analysis/[id]. User triggers floor plan → GA runs 80 generations → eco_score=82.3, orientation=15°.

Section 10

Key Design Decisions & Trade-offs

Crash-proof pipeline with synthetic fallbacks at every layer

Chosen: Every AI layer wraps inference in try/except with deterministic fallbacks. Endpoint never returns 500.

Trade-offs: Users may receive synthetic data silently. The soil_source field indicates data provenance.

Revisit when: SLAs require guaranteed data freshness.

XGBoost for flood risk (not deep learning)

Chosen: 6 tabular features don't benefit from deep learning. XGBoost achieves R²≈0.94, ~2ms inference, no GPU dependency.

Alternatives rejected: Random Forest (lower accuracy), linear regression (can't capture threshold effects), deep MLP (XGBoost won by 3 R² points in testing).

Known failure mode: Synthetic training data doesn't capture regional geological complexity — may underestimate risk in deltaic zones.

Genetic Algorithm optional, deterministic default

Chosen: GA only activated by generation_method="ga". Default deterministic layout is faster and reproducible.

Why GA for optional mode: 4-objective optimisation (solar/ventilation/trees/slope) in continuous geometry space — GA handles trade-offs without gradient computation.

Trade-offs: Non-deterministic; ga_seed parameter added. ~120ms vs ~5ms for deterministic.

asyncio.gather() for concurrent API calls

Chosen: All 7 API calls issued simultaneously → latency = slowest single call (~10s) vs ~35s sequential.

Trade-offs: Rate limits on SoilGrids/Overpass may cause 429 errors, caught by synthetic fallback.

SQLite default / PostgreSQL production

Chosen: Zero-config developer experience. DATABASE_URL env var switches to PostgreSQL without code changes. ORM handles UUID type differences via _IS_SQLITE flag.

Revisit when: First 100-user production deployment — SQLite has no concurrent write support.

React Three Fiber + procedural textures (no image files)

Chosen: 2,602 LOC in model3d page. Brick/concrete/wood textures baked via FBM noise onto CanvasTexture. NOOP_RAYCAST pattern fixes performance regression.

Trade-offs: ~600KB Three.js bundle. ThreeErrorBoundary catches WebGL context loss for graceful recovery on mobile.
